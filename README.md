# APPI Algorithm Disclosure Compliance Q&A Agent

AI agent for answering APPI 2026 algorithm disclosure and cross-border AI transfer compliance questions, built with Agentic Star.

> **Category**: Cat 2 (domain-specific pipeline agent for the FIN industry)
> **Industry**: Finance
> **Template ID**: FIN-C2-145

## Overview

Compliance Q&A agent for financial institutions preparing for Japan's amended Act on the Protection of Personal Information (APPI) as it applies to AI systems from July 6, 2026. It answers compliance officers' questions about algorithm disclosure duties for AI-driven credit scoring and investment recommendations, cross-border personal data transfer rules for AI training and inference, and third-party AI vendor contract requirements. Answers are composed from a curated knowledge base of regulatory articles, cite the applicable articles, classify the compliance risk level of the topic, and always carry a legal disclaimer; high-risk topics additionally carry an enforcement-deadline warning. Callers can restrict a question to a topic area and bound the number of cited articles per request.

This is an agent template built with the **AGENTIC STAR** development platform and the
**AgentCore Framework**. It is intended to be taken as a starting point: fork it, adapt it to
your own data and policies, and run it inside your own AGENTIC STAR deployment.

## Requirements

**This template does not run standalone.** It requires:

| Requirement | Notes |
|---|---|
| **AGENTIC STAR platform** | The agent connects to the platform at start-up. Without it, start-up fails immediately (see *Behaviour without the platform* below). Deployment guides and API documentation: [AGENTIC STAR Developers](https://developers.fd.agenticstar.tm.softbank.jp/) |
| **AgentCore Framework** (`agenticstar-agentcore`) | Installed from PyPI as a dependency. |
| Python | >=3.11 |

```bash
pip install -e .
```

### Behaviour without the platform

The framework is designed to run **only** on AGENTIC STAR. There is no fallback or degraded
mode. If the platform is unreachable or the SDK version does not match, the agent fails
during graph compile / start-up preflight rather than starting in a partially
working state. This is intentional — a half-running agent is worse than one that refuses to start.

## Quick Start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m pytest tests/ -v
```

Tests run without a platform connection. Running the agent itself does not.

## Project Structure

```
src/          agent implementation (nodes, services, schemas)
tests/        unit, integration and boundary tests
config/       agent configuration
docs/         design and operational documentation
```

See `docs/` for the design and the test specification.

## Customising

1. Adjust `config/` for your own environment and policies.
2. Replace the knowledge sources and sample data with your own.
3. Review the node implementations under `src/nodes/` for domain-specific logic.
4. Re-run the test suite.
